# DFN3: состояние перед нативной интеграцией

21 октября 2026, `miccontrol-8sd`. Рабочая основа — опубликованная Danygramm 1.2 с картами, source `1adbb1d8af08e4849da9cdc40e5a941a46d97a7f`. Пользователь подтвердил карты. Код приложения, пакет, подпись и ключи при исследовании звука не менялись.

Сравнение отдельных denoiser stages завершено: 43 одинаковых публичных входа и 129 выходов RNNoise 1.6 / GTCRN / DeepFilterNet3. Основной агент независимо проверил длину и конечность всех выходов, provenance общего входа, хеши DFN3, синтаксис обоих репродукторов и локальные ссылки. Повторная inference и UI-тесты для этой проверки не запускались. Независимый reviewer дополнительно проверил базовое сравнение GTCRN/RNNoise; его дополнительный review DFN3 прерван лимитом.

DFN3 — предпочтительный кандидат для следующего нативного прототипа: выигрыш SI-SDR в 25/27 смесей и 8/9 всплесков, лучшее подавление дождя и клавиатуры. Это не разрешение немедленно заменить обработку в APK: gain тихого начала clean_A за 100 мс — 0.033, clean_B — 0.178; после одного всплеска пылесоса — 0.008. Причина этих потерь не установлена. Штатная ветка `lsnr < -15` не объясняет их: конкретная модель ограничивает LSNR через `Sigmoid * 50 - 15`. Параметры не подбирались.

## Продолжение

1. Собрать безопасный нативный прототип DFN3 из pinned source `d375b2d8309e0935d165700c91da9de862a99c31` и неизменённого Cargo.lock. Модель: SHA-256 `c94d91f70911001c946e0fabb4aa9adc37045f45a03b56008cb0c8244cb63616`. Установлен только Homebrew rustup; `rustup toolchain list` пока пуст. Сборка Rust/NDK не начиналась, каталога `Tools/dfn3-native-probe` нет.
2. Для C ABI обработать ошибки без panic через `extern C`: upstream `df_create` использует `expect`. Создание и сброс модели должны происходить вне capture. `DfTract::init()` не считать полным сбросом: он не очищает все очереди и состояния. Проверить клонирование исходного холодного состояния.
3. Проверить host C API на тех же PCM, затем Android arm64 API 23 / NDK 27.2.12479018, ELF LOAD 16 КиБ, зависимости, размер и задержку. Не повышать minSDK. Нативный PCM CLI на эмуляторе допустим как отдельная проверка без интерфейса; его ещё не запускали.
4. Проверить полную цепочку APM с раздельным отключением NS/AGC для режима изоляции, сохранив AEC. Текущий порядок — WebRTC NS → AGC1 → RNNoise; проведённая матрица эту цепочку целиком не покрывает.
5. До подключения к приложению определить ограниченную очередь worker, постоянную задержку, поведение при недогрузке, очистку при переключениях и отсутствие старого звука после сброса. Не запускать тяжёлую inference или загрузку модели под capture lock. Режимы «Без эффектов» и обычного шумоподавления сохранить.

План интеграции ещё не создан; новая AI-изоляция не включена ни в один APK. Все три рабочих агента остановились из-за лимита использования Codex. Нет незавершённых процессов Cargo/rustup/brew.
