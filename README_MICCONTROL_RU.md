# Danygramm для Android

Собрал Danygramm на официальных исходниках Telegram Android 13.0.2 (7175), upstream commit `f32ffeec763f0bdbf4bec25b52d654f77bff733d`. Это моя неофициальная сборка с настройками микрофона и локальным переводом переписки.

## Установка

[Тестовая Danygramm 1.2](https://github.com/DV-Design/MicControl-Telegram/releases/download/danygramm-1.2/Danygramm-arm64.apk) · [Релиз и контрольная сумма](https://github.com/DV-Design/MicControl-Telegram/releases/tag/danygramm-1.2).

В 1.2 подключил карты; работу проверил на телефоне. Имя версии `13.0.2-danygramm-1.2`, code `71819`. Обработка микрофона такая же, как в 1.1: на громком фоне шум ещё слышен, а речь может прерываться. Этим занимаюсь отдельно на основе 1.2. UI-тесты для 1.1 и 1.2 не запускал.

[Стабильная Danygramm 1.0](https://github.com/DV-Design/MicControl-Telegram/releases/download/danygramm-1.0/Danygramm-arm64.apk) · [Релиз и контрольная сумма](https://github.com/DV-Design/MicControl-Telegram/releases/tag/danygramm-1.0). Она остаётся в стабильном канале обновления. Версия `13.0.2-danygramm-1.0`, code `71799`.

[Предыдущая тестовая 1.1](https://github.com/DV-Design/MicControl-Telegram/releases/download/danygramm-1.1/Danygramm-arm64.apk) содержит усиленное подавление окружающих звуков. Её версия `13.0.2-danygramm-1.1`, code `71809`.

Все эти APK для arm64, Android 6+ (min 23, target 36). Собираю вариант AfatStandalone с отключённой отладкой и без автоматического включения debug-логов. Минификацию оставил выключенной. Пакет `org.miccontrol.messenger.web` и сертификат SHA-256 `59e104c1d8b66e20c47119aed387993df655475cdd3153fb21bfb3752d85debe` сохраняются, поэтому обновление ставится поверх предыдущих версий без удаления данных. Нативные библиотеки поддерживают страницы памяти 16 КиБ.

Репозиторий публичный, вход в GitHub для скачивания APK не нужен. Android может запросить разрешение на установку из выбранного источника.

```bash
adb install -r artifacts/Danygramm-arm64.apk
```

Не удаляйте приложение перед обновлением: вместе с ним удалятся локальные данные. Если установка не проходит, не заменяйте ключ подписи другим.

## Микрофон

Во время личного аудио- или видеозвонка нажмите «Микрофон» внизу справа, над основными кнопками. Нижняя панель открывается по нажатию, выбранный режим отмечен радиопереключателем и контрастным фоном.

| Режим | Обработка |
|---|---|
| Изоляция голоса | WebRTC NS и RNNoise с усиленным подавлением шумовых частотных полос |
| Шумоподавление | WebRTC NS и обычная обработка голоса без RNNoise |
| Без эффектов | Без NS, RNNoise, автоматического усиления и дополнительного фильтра высоких частот |

Эхоподавление оставил под управлением движка звонка, чтобы не было обратной связи. Гарнитура может обрабатывать звук независимо от приложения. Режим меняется сразу и запоминается. Старое включённое состояние изоляции переносится в «Изоляцию голоса», прежний «Стандартный» в «Шумоподавление».

В стабильной 1.0 увеличил коэффициент спектрального подавления RNNoise с 1,00 до 1,30. На одном и том же синтетическом шуме нативный тест дал отношение остаточной энергии 0,718265 к предыдущей обработке, то есть снижение на 28,2%.

В тестовых 1.1 и 1.2 коэффициент равен 1,60. На записях дождя, пылесоса и клавиатуры получил снижение остаточного шума от 1,02 до 3,83 дБ по сравнению с 1.0; в паузах смешанных записей оно составило от 1,50 до 7,54 дБ. Общий уровень чистой речи почти сохранился, но отдельные тихие начала слов стали слабее. По этим измерениям нельзя обещать одинаковую разборчивость с любым шумом. Если обработка мешает речи, переключитесь на «Шумоподавление». Дополнительное приглушение по вероятности речи я в сборку не включил: результат оказался хуже.

RNNoise не распознаёт владельца голоса и может оставлять чужую речь. Выделение только одного говорящего пока отложил: [проверенный прототип](docs/reports/audio/2026-10/target-voice-model-evaluation.md) ошибался и в APK не вошёл. Сейчас занимаюсь подавлением окружающих звуков.

Групповые звонки и конференции оставил со штатной обработкой Telegram. Кнопка режима скрыта до ответа на входящий звонок, в группах, конференциях и PiP. Системные режимы AirPods или OriginOS она не переключает.

## Перевод переписки на экране

В меню ⋮ чата откройте «Перевод на экране» и включите перевод входящих сообщений. Для каждого чата можно выбрать свой язык. По умолчанию он совпадает с языком приложения. Панель над перепиской показывает состояние и открывает настройки перевода. Чтобы вернуться к исходному тексту, нажмите «Показать оригиналы сообщений».

Переводятся видимые входящие сообщения и подписи к фото, видео и файлам. Оригинальные TL-сообщения и их entities сохраняются, исходящие сообщения автоматически не переводятся. Опросы, статьи, распознавание голоса и элементы интерфейса остаются как были.

Для перевода использую [Google ML Kit Translation](https://developers.google.com/ml-kit/language/translation/android) и уже имеющееся определение языка. Модели скачиваются по мере необходимости, примерно 30 МБ на язык. По умолчанию загрузка идёт через Wi-Fi, мобильную сеть можно разрешить отдельно. После загрузки перевод работает локально и без интернета. Текст переписки сервису перевода не отправляется. Premium и отдельный API-ключ переводчика не нужны.

При ошибке, неизвестном языке или недоступной модели остаётся оригинал. Повторную попытку нужно запустить из меню: перерисовка чата сама не начинает загрузку заново. Скачанные модели можно удалять. Одновременно допускается до четырёх моделей неанглийских языков; при достижении лимита сначала удалите ненужные.

После закрытия чата или выключения перевода старые результаты не применяются. Уже начатую загрузку SDK отменять не умеет, поэтому она может завершиться в фоне.

## Работа в фоне и обновления

Откройте Настройки → Danygramm. Там можно включить фоновое соединение, перейти к разрешениям уведомлений и полноэкранных звонков, настроить батарею или проверить обновления.

Для фонового соединения использую существующий механизм Telegram. При авторизованном аккаунте его поддерживает тихая постоянная служба. Собственный Firebase-проект для этого не нужен, FCM в этой сборке не настроен. У службы тип Android `specialUse`; `dataSync` с временным лимитом для постоянного соединения не использую. Микрофон и камеру служба не включает.

Разрешите уведомления, работу без ограничений батареи и автозапуск, если OriginOS предлагает такую настройку. После принудительной остановки в настройках Android доставка возобновится только при следующем открытии приложения. Входящие сообщения и звонки после длительного сна ещё нужно проверить на vivo с авторизованным аккаунтом.

Обновления проверяются не чаще раза в сутки, а вручную их можно проверить в любой момент. Приложение читает последний стабильный релиз из этого GitHub-репозитория. APK скачивается только после нажатия. Перед установкой проверяются размер, SHA-256, пакет, возрастающий versionCode и сертификат. Файл с другой подписью или подменённым содержимым, а также откат версии будут отклонены. Саму установку выполняет системный установщик Android.

## Иконка

Оставил форму и пропорции бумажного самолётика Telegram, добавив две маленькие красные звезды на крыльях. В launcher и крупной иконке фонового уведомления используется цветной вариант. Маленькие значки строки состояния Android окрашивает в один цвет, поэтому там виден тот же силуэт самолётика.

## Сборка

Использую JDK 21, Android SDK platforms 35/36, Build Tools 36.0.0, NDK 27.2.12479018, CMake 3.22.1 и Gradle wrapper 8.13. Пример SDK/API настроек есть в [local.properties.example](local.properties.example).

Для своей API application получите `api_id` и `api_hash` на [my.telegram.org/apps](https://my.telegram.org/apps). Укажите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в исключённом из Git `local.properties` или переменных окружения. Не добавляйте их в исходники. Публичный sample API в standalone-сборке запрещён.

Для обновления уже установленного Danygramm нужен прежний `.local/miccontrol-debug.keystore`. Имя файла осталось от первых сборок, тем же ключом подписываю и вариант без debug. Скрипт не создаёт другой ключ автоматически и проверяет fingerprint до и после сборки. Сам ключ в публичный репозиторий не входит.

```bash
git submodule update --init --recursive --depth=1
./scripts/build-apk.sh
```

После сборки получаются:

- `artifacts/Danygramm-arm64.apk`
- `artifacts/Danygramm-arm64.apk.sha256`
- `artifacts/danygramm-update.json`
- `artifacts/maps-configuration.json`

Gradle APK лежит в `TMessagesProj_AppStandalone/build/outputs/apk/afat/standalone/app.apk`. Скрипт собирает только arm64, ограничивает Gradle двумя workers и heap 4 GB. Для локальной отладочной сборки есть `--debug`; у неё отдельный артефакт.

В GitHub Actions уже настроены `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `MICCONTROL_DEBUG_KEYSTORE_B64` и `GOOGLE_MAPS_API_KEY`. Workflow восстанавливает ключ подписи только на время сборки, проверяет сертификат и публикует APK, SHA-256, metadata обновления и `maps-configuration.json`. В последнем файле сохраняется проверка конфигурации карт без значения API-ключа. Для форка с другой подписью измените сборочную конфигурацию и pin сертификата обновлений.

### Google Maps

Для 1.2 добавил настройку `GOOGLE_MAPS_API_KEY`. Имя одинаковое для переменной окружения, записи в исключённом из Git `local.properties` и секрета GitHub Actions. Сборка подставляет ключ в metadata `com.google.android.geo.API_KEY`. В Actions ключ храню в одноимённом секрете. Для standalone-сборки ключ обязателен, в debug его можно оставить пустым.

В Google Cloud нужен ключ для Maps SDK for Android. Его можно извлечь из APK, поэтому задайте Android-ограничения:

- пакет `org.miccontrol.messenger.web`;
- SHA-1 сертификата `47:B9:97:83:0C:04:98:BF:3D:4D:61:8A:39:55:FB:CA:1D:28:0E:69`;
- в ограничениях API оставьте только Maps SDK for Android.

Для своей подписи укажите её SHA-1. [Инструкция Google по настройке ключа](https://developers.google.com/maps/documentation/android-sdk/get-api-key). Для локального перевода ML Kit этот ключ не нужен.

## Проверки

Точный объём проверок каждой версии собрал в [Android runtime tests](tests/miccontrol/ANDROID_RUNTIME_TESTS.md). Проверка сборки и подписи сама по себе не подтверждает получение сообщений или работу звонков. В dev3 18 октября получилось войти в личный аккаунт. Новые коды входа ради автоматических проверок не запрашиваю.

```bash
python3 tests/miccontrol/run_native_tests.py --sanitize
python3 tests/miccontrol/run_native_tests.py --sanitize --speech-wav path/to/48000hz-mono-pcm16.wav
```

ASan/UBSan покрывают RNNoise и resampling, mono/stereo 8/16/32/48 кГц, точный bypass, тишину, независимость каналов, повторные переключения и освобождение памяти. Для Android-проверок предыдущих сборок использовал реальный APK с его нативной библиотекой. Сборка 1.2 и опубликованный APK прошли статическую проверку; результат сохранил в [отчёте релиза](docs/reports/audio/2026-10/danygramm-1.2-release.md).

## Если код входа не приходит

Для личного аккаунта выключите Test Backend / Тестовый сервер на экране номера. Это отдельная среда, не связанная с обычным Telegram. Выбор сохраняется после обновления приложения. Если экран входа сообщает о коде через Telegram, этот способ доставки выбрал сервер. Приложение не может гарантированно заменить его на SMS. Подробнее об [авторизации Telegram](https://core.telegram.org/api/auth).

## Особенности и ограничения

- Google Sign-in, passkeys, официальные SMS Retriever подписи и Google Play Billing отключены. Остаётся вход по номеру с ручным вводом кода.
- Официальный updater Telegram отключил, Danygramm получает обновления из GitHub Releases.
- Собираю только arm64. В магазины приложение не публикую.
- Качество звонка, Bluetooth и ограничения батареи OriginOS ещё нужно проверить на реальном vivo/AirPods с собеседником.
